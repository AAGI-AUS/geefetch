## 1. Objective

Build a production-quality R package that provides a unified, Python-free interface for extracting spatio-temporal environmental covariates from Google Earth Engine, following `nert`'s proven architecture and documentation standard.

### Success Criteria

| Criterion | Measure |
|---|---|
| Installs without Python | `install.packages("geefetch")` works on clean R with no reticulate/conda |
| Core extraction works via REST API | Point extraction, time series, raster download for all Tier 1 datasets |
| `R CMD check --as-cran` | Zero errors, warnings, notes on macOS + Ubuntu + Windows |
| Test coverage | ≥80% line coverage |
| Documentation | Full roxygen2 reference, 3+ precompiled vignettes, pkgdown site |
| Batch extraction | `collect_gee_data()` handles 1000+ points × 10 datasets → `data.table` |
| Caching | Repeated identical calls served from disk cache with <10ms latency |
| nert interoperability | Same output conventions (`terra::rast()`, `data.table`), same naming pattern |

## 2. Architecture

### 2.1 Design Principles

1. **Follow nert exactly** where it makes sense — naming, dispatcher pattern, output types, documentation style.
2. **REST-first, rgee-fallback** — the REST API backend is the default; rgee is an optional power-user backend in Suggests.
3. **No tidyverse in Imports** — `data.table` for tabular, `terra` for spatial, `sf` for geometry. Same stack as nert.
4. **Modular handlers** — each GEE dataset is an internal handler function, registered via a static alias table.
5. **Aggressive caching** — disk-backed, hash-keyed, TTL-aware. Extraction is expensive; cache hits should be the norm.
6. **Informative failure** — every error uses `cli::cli_abort()` with context, suggestions, and examples. No cryptic stack traces.

```r
# --- read_gee.R ---

#' Read data from Google Earth Engine
#'
#' @description
#' Central dispatcher for all GEE dataset reads. Accepts a dataset identifier
#' (name or alias) and delegates to the appropriate internal handler.
#' For most use cases, prefer the convenience functions (e.g.,
#' [read_modis_ndvi()], [read_era5()]) which provide named parameters
#' and dataset-specific documentation.
#'
#' @param dataset_id Character. Dataset name or alias. Use `gee_datasets()`
#'   to list all available datasets.
#' @param ... Arguments passed to the dataset-specific handler. Common
#'   arguments include `date`, `collection`, `depth`. See the convenience
#'   function documentation for dataset-specific parameters.
#' @param backend Character. `"rest"` (default) or `"rgee"`. The REST backend
#'   requires no Python; the rgee backend supports advanced server-side
#'   computations.
#' @param cache Logical. Use disk cache for repeated queries? Default `TRUE`.
#' @param max_tries Integer. Maximum retry attempts for network failures.
#'   Default `3L`.
#' @param initial_delay Numeric. Initial delay in seconds before retry
#'   (doubles each attempt). Default `1`.
#'
#' @returns A [terra::rast()] SpatRaster object.
#'
#' @family GEE readers
#' @seealso [collect_gee_data()] for batch point extraction returning a
#'   [data.table::data.table].
#'
#' @examplesIf interactive()
#' # Using the dispatcher directly
#' ndvi <- read_gee("MODIS_NDVI", date = "2024-06-15")
#'
#' # Equivalent convenience function (preferred)
#' ndvi <- read_modis_ndvi(date = "2024-06-15")
#'
#' @export
read_gee <- function(dataset_id,
                     ...,
                     backend = c("rest", "rgee"),
                     cache = TRUE,
                     max_tries = 3L,
                     initial_delay = 1) {

  backend <- match.arg(backend)

  # 1. Resolve alias → normalised dataset ID
  did <- .gee_resolve_id(dataset_id)

  # 2. Capture and validate args before any network call
  dots <- list(...)
  .gee_validate_args(did, dots)

  # 3. Check authentication
  .check_gee_auth(backend)

  # 4. Check cache
  if (cache) {
    cached <- .cache_get(did, dots)
    if (!is.null(cached)) return(cached)
  }

  # 5. Dispatch to handler
  result <- switch(did,
    modis_ndvi      = .read_gee_modis_ndvi(dots, backend, max_tries, initial_delay),
    modis_lst       = .read_gee_modis_lst(dots, backend, max_tries, initial_delay),
    era5_temp       = .read_gee_era5(dots, "temperature_2m", backend, max_tries, initial_delay),
    era5_precip     = .read_gee_era5(dots, "total_precipitation", backend, max_tries, initial_delay),
    chirps_precip   = .read_gee_chirps(dots, backend, max_tries, initial_delay),
    srtm_elevation  = .read_gee_srtm(dots, backend, max_tries, initial_delay),
    slga_cly        = .read_gee_slga(dots, "CLY", backend, max_tries, initial_delay),
    slga_snd        = .read_gee_slga(dots, "SND", backend, max_tries, initial_delay),
    slga_awc        = .read_gee_slga(dots, "AWC", backend, max_tries, initial_delay),
    slga_phc        = .read_gee_slga(dots, "PHC", backend, max_tries, initial_delay),
    slga_bdw        = .read_gee_slga(dots, "BDW", backend, max_tries, initial_delay),
    slga_nto        = .read_gee_slga(dots, "NTO", backend, max_tries, initial_delay),
    sentinel2_ndvi  = .read_gee_sentinel2(dots, backend, max_tries, initial_delay),
    landsat_ndvi    = .read_gee_landsat(dots, backend, max_tries, initial_delay),
    .gee_not_implemented(dataset_id)
  )

  # 6. Cache result
  if (cache) .cache_set(did, dots, result)

  result
}
```

### 2.5 Batch Extraction: `collect_gee_data()` (mirroring `nert`)

Follows `nert`'s `collect_tern_data()` exactly: accepts coordinates + date range + dataset list, returns a single `data.table`.

```r
#' @param stat Character. For SLGA soil datasets: statistic.
#'   `"mean"`, `"ci_lower"`, `"ci_upper"`. Default `"mean"`.
#' @param backend Character. `"rest"` (default) or `"rgee"`.
#' @param cache Logical. Default `TRUE`.

#'   Default `FALSE`.
#'

#'   \item{<dataset columns>}{One column per requested dataset/variant}
#' }
#'
#' @section Column naming:

  # 1. .parse_coordinates(lon, lat, xy) → validated sf points
  # 2. .parse_date_range(date_range) → Date vector
  # 3. .validate_datasets(datasets) → resolved dataset IDs
  # 4. if (verbose) .print_datasets_table(datasets, date_range)
```

### 2.8 Caching Strategy

| Layer | Mechanism | Key |
|---|---|---|
| Disk (primary) | `.fst` files in `tools::R_user_dir("geefetch", "cache")` | SHA256 of `(collection, bands, coords_wkt, date, scale, reducer)` |
| Memory (session) | Named list in package environment | Same hash as disk |
| Invalidation | TTL: 30 days for dynamic datasets, infinite for static (SRTM, SLGA) | Per-handler metadata |
| Control | `cache = TRUE/FALSE` per call; `gee_clear_cache()` utility | — |

```r
# --- cache.R ---

.cache_dir <- function() {
  tools::R_user_dir("geefetch", "cache")
}

.cache_hash <- function(did, dots) {
  key_parts <- list(did = did, args = dots[order(names(dots))])
  digest::digest(key_parts, algo = "sha256")
}

.cache_get <- function(did, dots) {
  hash <- .cache_hash(did, dots)

  # Memory cache first

  mem <- .geefetch_env$mem_cache[[hash]]
  if (!is.null(mem)) return(mem)

  # Disk cache
  fpath <- file.path(.cache_dir(), paste0(hash, ".fst"))
  if (!file.exists(fpath)) return(NULL)

  # Check TTL
  meta <- .GEE_META[[did]]
  if (!is.null(meta$temporal) && meta$temporal != "static") {
    age_days <- as.numeric(difftime(Sys.time(), file.mtime(fpath), units = "days"))
    ttl <- getOption("geefetch.cache_ttl", 30)
    if (age_days > ttl) {
      unlink(fpath)
      return(NULL)
    }
  }

  fst::read_fst(fpath, as.data.table = TRUE)
}
```

### 2.9 Error Handling (mirroring `nert`)

All user-facing errors use `cli::cli_abort()`. The pattern matches nert exactly:

| Scenario | Handler | Message style |
|---|---|---|
| Unknown dataset | `.gee_not_implemented()` | Lists all valid datasets with aliases |
| Missing required arg (e.g., `date` for time-series) | `.gee_validate_args()` | Shows example code for the correct call |
| Invalid date format | `.validate_date()` | Shows expected format, suggests `lubridate::ymd()` |
| Not authenticated | `.check_gee_auth()` | Guides to `gee_auth()` with step-by-step instructions |
| REST API error (4xx/5xx) | `.rest_request()` | Translates HTTP error to human-readable message |
| rgee not installed (when `backend = "rgee"`) | `.rgee_extract_*()` | Suggests `install.packages("rgee")` or `backend = "rest"` |
| Network failure | `.retry_request()` | Exponential backoff, max retries, then informative abort |
| Batch extraction failure | `collect_gee_data()` | `cli::cli_warn()`, column → `NA`, continue |
| Coordinates out of bounds | `.validate_single_coord()` | Shows valid ranges, flags which coord is invalid |

## 9. Key Risks & Mitigations

| Risk | Severity | Likelihood | Mitigation |
|---|---|---|---|
| **REST API cannot handle all extraction patterns** (e.g., complex temporal composites, server-side map algebra) | High | Medium | Dual backend. Document which operations require rgee. REST handles 80%+ of common workflows. |
| **REST API `computePixels`/`computeFeatures` are still alpha** | High | Low | These endpoints have been stable since 2023. Pin to v1 where possible. Monitor changelogs. |
| **gargle auth is confusing for first-time GEE users** | Medium | High | `gee_setup()` wizard with step-by-step instructions. Vignette 1 includes screenshots. FAQ section. |
| **GEE project ID required for REST API** | Medium | High | Auto-detect from gargle token where possible. Clear error message with instructions if not. |
| **Rate limiting / 429 errors under heavy batch load** | Medium | Medium | Exponential backoff. Batch chunking. Cache eliminates repeat calls. |
| **CRAN reviewers flag gargle/httr2 usage** | Low | Low | Both are widely used CRAN packages (bigrquery, googlesheets4). Precedent is strong. |
| **nert API changes break cross-package conventions** | Low | Low | Pin conventions at design time. Both packages share an author (Adam Sparks). |

### What we explicitly will NOT build

Scope discipline is critical. geefetch will **not**:

- Do server-side computation (composites, band math, classification) — use rgee directly
- Provide mapping/visualisation — use `terra::plot()`, `ggplot2` + `tidyterra`, or `leaflet`
- Model environmental data — use `nlme`, `mgcv`, `ranger`, etc.
- Replace rgee — it complements rgee by handling the 80% case (extraction) much more easily
- Support non-GEE data sources — that's nert's job (TERN), or other specialised packages

## 10. Changes from v1 of This Document

| Section | What changed | Why |
|---|---|---|
| **Architecture** | Added dual REST/rgee backend as core design | Research revealed GEE REST API is production-stable. Python-free access is the #1 differentiator. No other R package does this. |
| **Dependencies** | Added `httr2`, `gargle`, `jsonlite`, `digest` to Imports. Removed `envfetch` entirely. | REST backend requires HTTP + auth packages. `envfetch` is too immature (v0.0.0.9000, `browser()` calls in production code, hard rgee dependency) to depend on — we adopt its good ideas (caching, batching) but implement them ourselves. |
| **Naming** | `gf_extract()` → `read_gee()`, `gf_collect()` → `collect_gee_data()`, `gf_ndvi()` → `read_modis_ndvi()` | Aligns with nert's `read_*()` / `collect_*()` convention. Cross-package consistency matters more than a custom prefix. |
| **Auth** | Replaced "rgee::ee_Initialize wrapper" with gargle-based OAuth | gargle is the standard R auth library for Google APIs. Users of googlesheets4/googledrive already have credentials. No Python needed. |
| **Caching** | Replaced "envfetch-based caching" with custom `digest` + `fst` implementation | Cannot depend on envfetch. Custom cache is simple (~100 LOC), fully controlled, and uses `tools::R_user_dir()` (CRAN-compliant). |
| **File structure** | Added complete file tree with per-file descriptions | v1 was vague about code organisation. Explicit structure prevents architectural drift during implementation. |
| **Vignettes** | Added precompilation strategy (`!precompile.R`) | Matches nert. Avoids GEE credential requirement at CRAN check time. Critical for CRAN acceptance. |
| **Testing** | Added httptest2 mocking strategy + CI matrix | v1 said "mock-based tests" without specifying how. httptest2 is the standard for testing httr2-based packages. CI matrix ensures cross-platform + both backends are tested. |
| **Timeline** | 8–12 weeks → 10–14 weeks | More realistic given the REST backend engineering effort. Dual backend adds ~2 weeks vs rgee-only. |
| **Scope** | Added explicit "will NOT build" section | v1 lacked scope boundaries. Clear exclusions prevent creep. |
| **envfetch dependency** | Removed entirely | v0.0.0.9000 with `browser()` calls in production, hard rgee dependency, and heavy tidyverse chain. We take the good ideas (caching pattern, batching, time intervals) and implement them cleanly in our own stack. |
| **Handler extensibility** | Added `gee_register_dataset()` with concrete API | v1 mentioned "community contributions" vaguely. Concrete registration function + vignette makes it actionable. |
| **Competitive analysis** | Embedded throughout rather than separate section | Design decisions should reference the competitive context (e.g., "no other R package does X") rather than being disconnected from it. |
